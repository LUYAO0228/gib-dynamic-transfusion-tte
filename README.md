# Dynamic RBC transfusion strategies in high-risk acute gastrointestinal bleeding

This repository contains the analytical code for a two-database target trial emulation of dynamic red blood cell (RBC) transfusion strategies in critically ill adults with high-risk acute gastrointestinal bleeding (GIB). The study evaluates a strategy of initiating RBC transfusion within six hours of time zero (T0) and a strategy of initial deferral with rescue permitted after a recorded hemoglobin (Hb) below 7.0 g/dL. MIMIC-IV and eICU-CRD are analyzed separately.

## Study design

Eligibility uses the first qualifying hospitalization and ICU stay, an ICU stay of at least six hours, a coded acute GIB phenotype, and ischemic heart disease or hemodynamic instability. The phenotype uses database-specific codes and recorded indicators. Use the source definitions in `mimic.py`, `eicu.py`, and `eligibility.py` when interpreting anatomical and etiologic scope. The main cohort uses the first qualifying Hb of 7.0 to below 9.0 g/dL within 72 hours of ICU admission. The timing analyses restrict this cohort to T0 within 48 hours or 24 hours of ICU admission and re-estimate the weights within each subset. Lookback intervals for baseline labs and vital signs are defined relative to T0. The primary analysis aligns MIMIC timestamps to ICU admission and uses ICU-centered offsets for eICU.

Each eligible stay contributes one clone to each strategy. The code applies artificial censoring when the observed treatment or ICU exit history becomes incompatible with the assigned strategy. A rescue Hb measurement must precede the restrictive-arm transfusion by the applicable timestamp rule. The hourly covariate history uses information available at the beginning of each interval. Inverse probability of censoring weights (IPCW) account for remaining compatible with the assigned strategy.

The primary endpoints are 28-day all-cause mortality in MIMIC-IV and 28-day in-hospital mortality in eICU-CRD, with live discharges retained in the latter estimand. Effects are reported as early initiation minus deferral for risk differences and early initiation divided by deferral for risk ratios. Bootstrap inference resamples participants in MIMIC-IV and hospitals in eICU-CRD. The calendar analysis uses MIMIC-IV anchor-year groups to represent calendar era. The shifted ICU admission year is used for a descriptive comparison.

## Data access and local layout

This repository contains no patient-level data. Get individual credentialed access through PhysioNet, complete the required CITI Data or Specimens Only Research training, and sign the applicable data use agreement (DUA) for each database. Keep downloaded files, derived patient-level tables, and results generated by the scripts in the credentialed environment. The MIT license applies to the analytical code.

- [MIMIC-IV v3.1](https://physionet.org/content/mimiciv/3.1/) (DOI `10.13026/kpb9-mt58`)
- [eICU-CRD v2.0](https://physionet.org/content/eicu-crd/2.0/) (DOI `10.13026/C2WM1R`)

Use the following repository-relative layout. `config.py` defines all paths. Keep source table names lowercase and preserve the source columns and time units.

```text
data/
  mimic-iv-3.1/
    hosp/                         # Official MIMIC-IV hospital CSV files
    icu/                          # Official MIMIC-IV ICU CSV files
  eicu-crd-2.0/                   # Official eICU-CRD CSV files
  parquet/
    MIMIC_hosp/                   # Optional matching hospital Parquet exports
    MIMIC_ICU/                    # Optional matching ICU Parquet exports
    mimiciv_derived/              # Required MIMIC-IV concept Parquet exports
    eICU/                         # Required ventilation_events; optional base-table mirrors
outputs/                          # Created by the workflow
```

The readers accept `.csv.gz` or `.csv` for the ordinary source tables. Use `.parquet` for the concept exports. Parquet mirrors take precedence where the code permits them. Keep the official MIMIC-IV v3.1 `patients`, `admissions`, `diagnoses_icd`, `d_icd_diagnoses`, `d_labitems`, `labevents`, `transfers`, and `icustays` CSV files available as the source and release-validation reference. The additional MIMIC-IV base inputs are `procedures_icd`, `d_icd_procedures`, `emar`, `hcpcsevents`, `chartevents`, `d_items`, `inputevents`, and `procedureevents`. The ordinary eICU base inputs are `patient`, `diagnosis`, `pasthistory`, `lab`, `intakeoutput`, `treatment`, `infusiondrug`, `vitalperiodic`, `vitalaperiodic`, `apachepatientresult`, `respiratorycharting`, and `medication`.

Generate or export the `bg`, `vitalsign`, `ventilation`, `vasoactive_agent`, and `norepinephrine_equivalent_dose` MIMIC-IV concepts using the [MIT-LCP MIMIC code repository](https://github.com/MIT-LCP/mimic-code/tree/main/mimic-iv). Export the credentialed eICU `ventilation_events` concept with `patientunitstayid`, `event`, and `hrs` from the matching eICU derived tables, as referenced in the [MIT-LCP eICU SQL](https://github.com/MIT-LCP/eicu-code/blob/main/concepts/pivoted/pivoted-oasis.sql). Use concept versions compatible with the database releases and retain their provenance locally. The extraction checks reference cohort counts to surface source-version or concept discrepancies.

## Software environment

Use 64-bit Python 3.11 and the pinned packages in `requirements.txt`. The Python implementation uses DuckDB for data extraction and PyArrow, NumPy, pandas, SciPy, Patsy, and scikit-learn for data processing and estimation. R is unnecessary. Large scans and bootstrap refits require local scratch space and can take several hours. Adjust `--workers` to available CPU and memory.

```bash
python -m venv .venv
```

Activate the environment with `source .venv/bin/activate` on macOS or Linux, or `.venv\Scripts\Activate.ps1` in PowerShell.

```bash
python -m pip install -r requirements.txt
python -B reproduce.py check-transitions
python -B reproduce.py 01
python -B reproduce.py 02
python -B reproduce.py 03 --workers 4
```

## Reproduction workflow

| Directory | Main operations and local outputs |
| --- | --- |
| `01_cohort_extraction/` | Validates the database release and timing, applies inclusion and exclusion criteria, builds baseline and time-varying covariates, and writes the private DuckDB handoff and sensitivity inputs. |
| `02_clone_censor_weight/` | Tests strategy boundaries with synthetic transitions, clones each stay, assigns artificial censoring, and writes baseline, hourly risk-set, and clone outcome files to `outputs/processed/`. |
| `03_ipcw_modeling_and_sensitivity/` | Fits censoring models using outcome-free features and checks covariate balance, weight behavior, and effective sample size before outcome modeling. Exports effect estimates, subgroup interactions, calendar-era and T0 restrictions, fixed-early-weight sustained deferral (`unified_sensitivity_and_sustained.py`), unified primary-specification sensitivity analyses S1–S9 (`B = 500`), retransfusion analyses, and quantitative bias analysis. |

Reference estimates and diagnostics are written under `outputs/reference/tables/`. Calendar, timing, unified S1–S9, and fixed-early-weight sustained-deferral estimates are written under `outputs/sensitivity/tables/`. To run the unified S1–S9 and sustained-deferral analyses after `python -B reproduce.py 03`, run `python -B 03_ipcw_modeling_and_sensitivity/unified_sensitivity_and_sustained.py --workers 4`. Sensitivity scenarios that fail the weight or balance criteria retain their diagnostics. Estimable results are exported regardless of statistical significance.

The workflow uses locally generated checkpoints. Start with a fresh `outputs/` directory when changing source data, concept exports, software versions, or analysis definitions. Treat the generated DuckDB, Parquet and checkpoint files as restricted and use checkpoints only from a trusted local run.
